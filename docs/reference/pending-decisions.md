# 保留中の判断事項

**技術で決められず、人が決める必要がある事項の一覧である。**
実装を進めるなかで「これは自分では決められない」と判断したものをここへ集約する。

[未解決の課題](../guides/implementation-roadmap.md#未解決の課題全体) との違いは次のとおり。

| | 未解決の課題 | この文書 |
|---|---|---|
| 性質 | 調べれば分かる。手を動かせば進む | **調べても決まらない。判断が要る** |
| 解消のしかた | 実装・実測・調査 | ユーザーまたは関係者への確認 |

## 使い方

- 実装中に判断事項が出たら**すぐここへ足す。** 会話の中だけに置かない
- 判断がついたら**行を消さず「済」へ移し、決定日と決定内容を残す。**
  後から「なぜそう決めたか」を辿れるようにする
- 判断が実装方針を変えるものは、あわせて
  [decisions/](../decisions/) に ADR を起こす

## 済

### 4. 配信先 —— ✅ **決定(2026-08-05)**

**当面は配信しない。**ローカルで遊べる状態で止める。

静的サイトなので、必要になった時点で配信先を決めればすぐ配れる
(`dist/` をそのまま置くだけ)。**決まらないうちに `base` の設定や配信ワークフローを
作ると、使われない設定が残る。**

→ [実装の進め方と現在地](../guides/implementation-roadmap.md) の工程 5

### 1. 技術構成 —— ✅ **決定(2026-08-05)**

React + TypeScript(要件)を前提に、**pnpm workspaces のモノレポ + Vite + Vitest** を採用。
`core` / `generator` / `web` の 3 パッケージに分ける。

→ [ADR 0001 プロジェクト構成](../decisions/0001-project-structure.md)

**UI ライブラリは Mantine。** 5 候補を実測比較して決めた。
決め手は「ホットキーと localStorage のフックが公式に揃っている唯一の候補だったこと」と
「`@layer mantine` により自前の盤面 CSS が常に勝つこと」。

→ [ADR 0002](../decisions/0002-ui-library-selection.md) /
[調査](../reports/2026-08-05-ui-library-survey.md)

⚠️ **この決定により React 19.2 以上が必須になった。**

### 2. サーバを持つか —— ✅ **決定(2026-08-05)**

**持たない。** 問題は事前生成した静的ファイルとして配信し、記録はブラウザ内に閉じる。

→ [ADR 0003 問題を事前生成した外部ファイルとして持つ](../decisions/0003-external-puzzle-files.md)

将来サーバを持つことにしても、**ファイル形式は契約として残せる**(配信元が変わるだけ)。

### 3. 対象範囲 —— ✅ **決定(2026-08-05)**

| 項目 | 決定 |
|------|------|
| 盤面の種類 | **9×9 のみ。** 4×4 / 16×16 / 変則ルールは作らない |
| オフライン対応 | **当面やらない。** PWA 化は対象外 |
| 難易度 | **難易度を指定して生成できるようにする。**手筋ソルバを実装して評価する |

→ [プロジェクトの目的と対象範囲](../overview/project-purpose.md) の「対象範囲」

**難易度の指定を要件に入れたことで、手筋ソルバの実装が必須になった**
([難易度の評価](../algorithms/difficulty-rating.md))。
手がかり数で代用する道は、人間の体感との相関が 0.25〜0.27 しかないため取れない。
