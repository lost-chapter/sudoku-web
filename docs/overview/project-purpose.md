# プロジェクトの目的と対象範囲

sudoku-web は、**ブラウザで数独を遊ぶための Web アプリケーション**である。

## 与えられた要件

2026-08-05 にユーザーから提示された 5 点。**これが設計の出発点である。**

| # | 要件 | 設計への効き方 |
|---|------|--------------|
| 1 | React + TypeScript | UI は React。ロジックも含めて全面 TypeScript |
| 2 | UI は最適なライブラリを用いる | [ADR 0002](../decisions/0002-ui-library-selection.md) で選定 |
| 3 | 数独を遊ぶためのシステム | 遊べることが完成条件。問題を作るだけでは足りない |
| 4 | **問題を外部ファイル化する** | 問題はコードに埋め込まない。配信可能なファイルとして持つ |
| 5 | **問題は大量に生成できる** | 生成はバッチ処理。アプリの実行時に作らない |

**4 と 5 がこのプロジェクトの構造を決めている。**
問題を「アプリの外にあるデータ」として扱うため、**問題を作る側**(Node で動くバッチ)と
**問題を遊ぶ側**(ブラウザで動くアプリ)が分かれ、その境界が
[問題ファイルの形式](../api/puzzle-file-format.md) という契約になる。

## 対象範囲

### 作るもの

| 領域 | 中身 |
|------|------|
| 盤面ロジック | 盤面の表現・入力の検証・解法(ソルバ)・完成盤の生成・穴あけ・難易度評価 |
| 問題の生成 | 大量生成する CLI。一意解の保証と難易度の分類まで行う |
| 問題ファイル | 生成結果を配信可能な形で持つ。アプリは fetch で読む |
| 遊ぶ UI | 難易度を選んで問題を開き、数字とメモを入力し、完成を判定するまで |
| 進行の保存 | 遊びかけの盤面をブラウザに保存し、再訪時に続きから遊べる |

### 作らないもの(現時点)

- **サーバ**。記録もランキングもブラウザ内に閉じる([ADR 0003](../decisions/0003-external-puzzle-files.md))
- **アカウント・ログイン**
- **9×9 以外の盤面**(4×4 / 16×16 / ジグソー / 変則ルール)
- **対戦・協力プレイ**
- **問題の実行時生成**。問題は事前に作ってファイルに置く(要件 5 の帰結)

**「作らない」は「永久に作らない」ではない。** 対象外を広げるときは
[保留中の判断事項](../reference/pending-decisions.md) を経由して決める。

## 完成の判定

**「遊べること」が完成条件である。** 具体的には次の 3 つが同時に満たされたとき。

1. 難易度を選んで問題を開き、最後まで解いて完成と判定される
2. 遊びかけを閉じても、次に開いたときに続きから遊べる
3. 収録した問題が**すべて一意解**であることをテストで保証できている

## 用語

| 用語 | 意味 |
|------|------|
| セル | 盤面の 1 マス。9×9 で 81 個 |
| ブロック | 3×3 の区画。9 個 |
| バンド / スタック | ブロック 3 つぶんの横並び / 縦並び |
| 手がかり(givens) | 最初から数字が入っているセル。ヒントとも呼ぶが、本プロジェクトでは
  遊技中の補助機能と紛れるため**「手がかり」で統一する** |
| 候補 / メモ | そのセルに入りうる数字。遊技者が手で書くものと、ソルバが計算するものがある |
| 解 | 盤面を埋めきった状態。数独として正しい問題は解がちょうど 1 つ(**一意解**) |
| 手筋 | 人間が使う解法の型(naked single, hidden single など) |
| 問題(puzzle) | 手がかりの配置。ファイルに収録される単位 |
| パック | 問題をまとめたファイル。配信の単位 |

数独の手筋の詳細は [難易度の評価](../algorithms/difficulty-rating.md) にある。
