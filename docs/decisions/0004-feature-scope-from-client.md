# 0004 遊技機能の範囲を発注者の要望に合わせる

## ステータス

採用(2026-08-06)

## 背景

工程 4 まで実装したあと、**発注者から遊技機能の要望が届いた。**
実装済みの機能のうち **3 つが「いらない」と名指しされた。**

⚠️ **これは不具合の報告ではない**。動作は仕様どおりで、
[画面構成と操作仕様](../ui/screens-and-interactions.md) にも書いてあった。
**遊技の設計として要らない、という判断である。**

| 発注者の言葉 | 実装の状態 |
|------------|----------|
| 候補数字のメモ機能 | ✅ 実装済み |
| 押した数字と同じ数字が色づく | ✅ 実装済み(同じ数字の強調) |
| 途中でやめて、再開できる | ✅ 実装済み(進行の保存) |
| **あきらめるボタンを押したら、最後に正解が分かる** | ❌ **未実装** |
| ❌ 音 | もともと無い |
| ❌ **タイマーとかスコア** | ⚠️ **経過時間を表示していた** |
| ❌ 列が完成したら色づく | もともと無い |
| ❌ **間違ってると教えてくる** | ⚠️ **誤りの即時指摘と矛盾の表示** |
| ❌ **出し尽くした数字が候補から消える** | ⚠️ **残り数の表示が 0 の数字を落としていた** |
| △ 数字を押したら、その数字がある行と列が色づく(あってもいい) | 近いものはある(選択セルの行・列・ブロック) |

## 決定内容

**「いらない」と言われた機能は、設定で切れる形にせず、実装ごと削除する。**

| 削るもの | 何を消すか |
|---------|----------|
| 経過時間 | 画面の表示・完成モーダルの所要時間・`useElapsedTime`・**進行の保存の `elapsedMs`** |
| 誤りの即時指摘 | `showMistakes` と `.mistake` |
| **矛盾(規則の重複)の表示** | `showConflicts` と `.conflict` |
| 残り数の表示 | `showRemaining`・パッドの残り数・**入りきった数字を落とす挙動** |

**設定に残さない。** 設定項目が増えるほどスマートフォンでの操作が煩雑になり、
**「いらない」と言われたものを選べる状態にしておく理由が無い。**

⚠️ **`core` の `findConflicts` は残す。** 盤面ロジックとしては正しく、
**呼ばれなくなるだけ**である。消すと、あとで要ると言われたときに書き直しになる。

**あきらめるボタンを追加する。** 押すと解が出て、そこで遊技が終わる。

## 判断理由

- **「間違ってると教えてくる」に矛盾の表示も含めた**(2026-08-06・ユーザー判断)。
  規則の重複は「答え」ではなく「自分の入力の中の食い違い」だが、
  **遊技者から見れば同じく「教えてくる」ものである**。線を引くと説明が要る
- **あきらめる導線があるので、誤りを指摘しなくても詰まらない。**
  行き詰まったら諦めて解を見られる。**指摘は救済としても不要になった**
- **タイマーは急かす。** [画面構成と操作仕様](../ui/screens-and-interactions.md) は
  「急かす演出はしない」と書いていたが、**表示すること自体が急かしている**
- **設定で切るより消すほうが、あとから読む人に正確である。**
  設定に残っていると「使うかもしれない機能」に見える

## 採用しなかった選択肢

| 選択肢 | 却下理由 |
|--------|---------|
| 設定に残して既定を切にする | 「いらない」と言われたものを選べる状態にする理由が無い。スマートフォンで設定が長くなる |
| 矛盾の表示だけ残す | ⚠️ **一度は推奨したが、ユーザーが「両方消す」と判断した**。遊技者から見れば同じく「教えてくる」ものである |
| 残り数の数字だけ残し、落とす挙動をやめる | 「スコア的な情報を消す」という要望に対して中途半端。**表示ごと消すほうが素直** |
| `core` の `findConflicts` も消す | 盤面ロジックとしては正しい。**呼ばないことと、間違っていることは別である** |

## 影響

- ⚠️ **進行の保存形式が変わる**(`elapsedMs` が無くなる)。
  古い保存を読んだときに壊れないこと。
  [問題ファイルの形式](../api/puzzle-file-format.md) の「進行の保存」を更新する
- **設定は 3 つに減る**(テーマ・同じ数字の強調・行列ブロックの強調)
- **`core` に未使用の関数が残る**(`findConflicts`)。
  [解法(ソルバ)](../algorithms/solver.md) の `findHint` と同じ状態である ——
  **「用意してあるが UI からは呼ばない」ことを文書に書く**
- **テストが減る。** ⚠️ **消した機能のテストを消すのはよいが、
  「消したから通った」ものが無いかを確認すること**
- 「数字を押したらその行と列が色づく」は**あってもいい**扱いなので、
  いまの「選択セルの行・列・ブロックの強調」で足りると判断する。
  **要望との差は残るので、遊んでみて足りなければ変える**
