# 検証: 難易度クラスの分布(基本手筋まで実装した時点)

## 目的

**難易度クラスのしきい値を確定するための分布を実測する**
([未解決の課題](../guides/implementation-roadmap.md#未解決の課題全体) の 2)。

[難易度の評価](../algorithms/difficulty-rating.md#難易度クラス) は
「しきい値は暫定。実際の分布を見ないと『ふつう』だけが極端に多いといった偏りが起きる」
と書いていた。**その偏りが本当に起きるかを見る。**

同時に、[同梱パックの件数](../guides/implementation-roadmap.md#未解決の課題全体)(課題 1)の
判断材料として、**難易度クラスごとに 1 問作るのに要る時間**を測る。

## 実施日・条件

| 項目 | 値 |
|------|-----|
| 実施日 | 2026-08-05 |
| 対象コミット | `packages/core` の `technique-solver.ts` + `difficulty.ts` 実装直後 |
| 機械 | Apple M1 Ultra(20 コア)/ Node.js v24.18.0 / 単スレッド |
| **実行のしかた** | **`node` で直接実行**(Vitest では 5〜7 倍遅く出る。[検証](2026-08-05-puzzle-generation-benchmark.md#-実行環境で数値が-57-倍変わる2026-08-05-追記)) |
| `load average` | 12 前後(他のセッションが動いている状態) |
| 標本 | **5,000 問**(1 つの乱数から連続生成し、1 問ずつ評価) |
| 実装済みの手筋 | **レベル 1〜4**(Single / Locked Candidates / Naked・Hidden の Pair・Triple・Quad) |

## 結果

### 所要時間

| 項目 | 値 |
|------|-----|
| 生成 + 評価 | **1.71 ms/問**(`node` 実行時。Vitest 上では 8.0〜8.1 ms/問) |
| うち評価だけ | **0.14 ms/問**(全体の約 8%) |

**難易度評価は安い。** 律速は穴あけのままである
([検証: 問題の生成](2026-08-05-puzzle-generation-benchmark.md))。

### 難易度クラスの分布(5,000 問)

| クラス | 問数 | 割合 | スコア(最小 / 中央 / 最大) | 手数中央 | **そのクラスを 1 問得るまで** |
|--------|------|------|--------------------------|---------|------------------------|
| やさしい `easy` | 2,017 | **40.3%** | 55 / 70 / 90 | 57 | 4.2 ms |
| ふつう `normal` | 571 | **11.4%** | 62 / 84 / 130 | 59 | 14.9 ms |
| むずかしい `hard` | 339 | **6.8%** | 67 / 101 / 177 | 62 | 25.2 ms |
| 難問 `expert` | 0 | 0.0% | — | — | 作れない |
| 最難関 `extreme` | 0 | 0.0% | — | — | 作れない |
| **評価できない** | 2,073 | **41.5%** | 7 / 56 / 143 | 24 | 4.1 ms |

**「評価できない」= 実装済みの手筋(レベル 1〜4)では解けなかった問題。**
⚠️ **これを「最難関」と分類してはいけない。**
それは「難しい」ではなく「評価できていない」である
([難易度の評価](../algorithms/difficulty-rating.md#実装していない手筋の扱い))。

## 考察

### 偏りは実際に起きた。ただし懸念とは逆向き

文書が警戒していたのは「**ふつう**だけが極端に多い」偏りだったが、
実測は **やさしい 40.3% と 評価できない 41.5% の 2 つに山**ができた。
**ふつうとむずかしいを合わせても 18.2% しかない。**

**原因は手筋の分布そのものである。** 生成された問題の多くは
Single だけで解け(= やさしい)、そうでないものは一気に
基本手筋の外へ出てしまう(= 評価できない)。
**Locked Candidates と Pair/Triple/Quad で「ちょうど解ける」帯が薄い。**

### しきい値をいま動かしてはいけない

**しきい値の見直しはレベル 5 以降の実装後にする。** 理由は 2 つ。

- **いま `expert` と `extreme` は 0% だが、これは「難しい問題が作れない」のではなく
  「評価できていない」だけである。** 41.5% の大半がそこへ移る見込み
- **移った後の分布を見ないと、どこで切るべきか判断できない。**
  いまのしきい値を動かすと、レベル 5 以降を足したときに二度手間になる

**⇒ 課題 2(難易度クラスのしきい値)は閉じない。** 判断材料が半分しか揃っていない。

### 同梱パックの件数は生成時間で制約されない

**最も高い `hard` でも 1 問 25.2 ms。** 1,000 問なら **約 25 秒**である。

| クラス | 1,000 問の生成に要る時間 |
|--------|----------------------|
| `easy` | 約 4.2 秒 |
| `normal` | 約 15 秒 |
| `hard` | 約 25 秒 |

**⇒ 課題 1(同梱パックを何問にするか)の制約は生成時間ではない。**
残る観点は**ファイルサイズと配信**である(1,000 問で約 164 KB)。

⚠️ **レベル 5 以降を実装すると `expert` / `extreme` の採用率は
`hard` よりさらに低くなる見込み**(いまの `hard` が 6.8%)。
**そのときは並列化(工程 2 の 6)が効いてくる。**

### スコアはクラス内の並べ替えに使える

**中央値はクラスの順に単調に増えた**(70 → 84 → 101)。
ただし**範囲は大きく重なっている**。`easy` の最大 90 は `normal` の中央 84 を超え、
`normal` の最小 62 は `easy` の中央 70 を下回る。

**⇒ スコアでクラスを決めてはいけない。** クラスは最難手筋で決め、
スコアは**同じクラスの中での並べ替えにだけ使う**という設計どおりに使う。

## 結論

- **難易度評価は安い(0.14 ms/問)。** 律速は穴あけのまま
- **分布は 2 山になった。**「やさしい」40.3% と「評価できない」41.5%
- **`expert` / `extreme` は現状 0%。** レベル 5 以降の手筋を実装するまで作れない
- **課題 1(パックの件数)の制約は生成時間ではない。** ファイルサイズと配信で決める
- **課題 2(しきい値)はまだ閉じない。** レベル 5 以降を実装してから見直す

## 追記(2026-08-05・管理役): 独立に再現した

統合時の裏取りで、**300 問を別に生成して分布を測り直した**(agent-b とは別の実装で集計)。

| クラス | 本レポート(5,000 問) | 管理役の再測(300 問) |
|--------|---------------------|---------------------|
| やさしい | 40.3% | 42.3% |
| ふつう | 11.4% | 9.7% |
| むずかしい | 6.8% | 7.0% |
| **評価できない** | **41.5%** | **41.0%** |

**標本数の違いを考えれば一致している。**

🎯 **同時に「難易度が手がかり数で決まっていない」ことも実測で確かめた。**

| クラス | 手がかり数の範囲 | 平均 |
|--------|----------------|------|
| やさしい | 22〜28 | 24.4 |
| ふつう | 22〜26 | 24.2 |
| むずかしい | 22〜26 | 24.3 |
| 評価できない | 22〜27 | 24.4 |

**どのクラスも平均 24.2〜24.4 で差が無い。**
[難易度の評価](../algorithms/difficulty-rating.md#-手がかり数で難易度を決めてはいけない) が
要求している「手がかり数を指標にしない」が、実装で実際に成り立っている。

決定性(同じ盤面から同じ判定・同じ手順)と、
**手筋が消した候補が解の数字でないこと**(20 問)も別途確認した。

## 追記(2026-08-05): レベル 5〜7 を実装した後の分布

**工程 2 の 7 で X-Wing / Swordfish / Jellyfish(5)、XY-Wing / XYZ-Wing(6)、
X-Chain(7)を実装した。**同じ 5,000 問・同じ乱数で測り直した
(`tsx` 実行 / `load average` 9.8〜10.0 / Apple M1 Ultra)。

| クラス | 実装前 | **実装後** | スコア(最小 / 中央 / 最大) | 1 問得るまで |
|--------|--------|-----------|--------------------------|------------|
| やさしい `easy` | 40.3% | **40.3%** | 55 / 70 / 90 | 4.2 ms |
| ふつう `normal` | 11.4% | **11.4%** | 62 / 84 / 130 | 14.9 ms |
| むずかしい `hard` | 6.8% | **6.8%** | 67 / 101 / 177 | 25.1 ms |
| 難問 `expert` | 0% | **5.3%** | 106 / 154 / 299 | 32.1 ms |
| 最難関 `extreme` | 0% | **6.1%** | 133 / 211 / 494 | 28.1 ms |
| **評価できない** | 41.5% | **30.1%** | 9 / 77 / 411 | — |

🎯 **やさしい・ふつう・むずかしいの問数は 1 問も動かなかった**(2,017 / 571 / 339)。
**低いレベルで解ける問題の評価は、手筋を足しても変わらない**ためである
(簡単な手筋から順に試すので、上位の手筋は出番が来ない)。
**実装が設計どおりに動いていることの裏付けになる。**

**評価できなかった 2,073 問のうち 568 問(27%)が難問・最難関へ移った。**
残る 1,505 問(30.1%)は、さらに上の手筋(Forcing Chain など)が要る。

### 手筋ごとの出現率(5,000 問)

| 手筋 | 出現 | 手筋 | 出現 |
|------|------|------|------|
| Hidden Single | 99.3% | X-Wing | 4.0% |
| Naked Single | 95.8% | Swordfish | 1.2% |
| Pointing | 52.9% | Jellyfish | 0.1% |
| Claiming | 25.5% | XY-Wing | 9.8% |
| Naked Pair | 22.3% | XYZ-Wing | 5.4% |
| Hidden Pair | 15.1% | **X-Chain** | **13.1%** |
| Naked Triple | 3.8% | Hidden Triple | 1.1% |
| Naked Quad | 0.1% | Hidden Quad | 0.0% |

**X-Chain がいちばん効いた**(13.1%)。単一数字の彩色は、
盤面全体をまたぐ関係を 1 つの手筋で拾えるためである。

⚠️ **Hidden Quad は 5,000 問で 1 度も出なかった。** 実装はしてあるが、
**この分布では出番が無い**。消す判断はしない(出ないことと誤りは別である)。

### 評価は少し高くなった

難易度評価そのものは **0.14 → 0.25 ms/問**。
上位の手筋を試す分だけ増えたが、**生成 + 評価は 1.70 ms/問 のまま**で、
律速は穴あけのままである。

### しきい値は動かさない(課題 2 の結論)

**5 クラスすべてに問題が行き渡り、極端な偏りは無くなった。**

- やさしい 40.3% は多いが、**遊技者が最初に触るクラスなので在庫が多いことは害ではない**
- ふつう〜最難関は 5.3〜11.4% に収まっており、**1,000 問のパックを 5 秒以内に作れる**
- スコアの範囲はクラス間で重なるが、**クラスは最難手筋で決めるので影響しない**

**⇒ 課題 2(難易度クラスのしきい値)は、いまのしきい値のままで閉じてよい。**
