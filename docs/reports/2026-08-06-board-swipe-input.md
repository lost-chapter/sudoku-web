# 盤面スワイプ入力の実装記録(2026-08-06)

## 結論

スマートフォンのセルからスワイプして数字を入力する機能を実装した。
**セルを選ぶ → 少し押してエリアを表示する → タップ終了時のエリアで入力する**を 1 回の操作で行える。

以前の検討で落とした「長押しから放射状メニュー」の案とは異なり、長押しも放射状の角度判定も使わない。
タップ開始から約 180ms 後に、タップしたセルの中心を基準に `1 2 3 / 4 5 6 / 7 8 9` の大きなエリアガイドを出し、
iPhone 純正キーボードのキーガイドに似た大きな数字表示を指の近くに出す。
指の位置は方向ベクトルではなく、表示中のエリアに対して判定する。

## 操作

| 操作 | 結果 |
|------|------|
| セルに触れる(タップ開始) | セルを選択する。短いタップではガイドを表示しない |
| 約 180ms 押し続ける | タップしたセルの中心に 3×3 の大きなエリアガイドを表示する。中央エリアの 5 を強調する |
| 指を動かす | 指が入ったエリアを青く強調し、大きな数字ガイドも切り替える |
| 指を離す | 指を離したエリアの数字を入力する。ガイドの外で離した場合は取り消す |
| ほぼ動かさずにタップを終える | 数字は入力せず、セルの選択だけを確定する |

数字の対応は、表示した 3×3 のエリアマップで行う。左上が 1、上中央が 2、右下が 9 になる。
メモモード中は通常の数字パッドと同じくメモとして入力し、手がかりのセルと完成後の盤面は受け付けない。

## スクロールと文字選択

スマートフォンのページ全体・ゲーム画面・盤面領域に対して次を設定した。

- `touch-action: none`
- `user-select: none` / `-webkit-user-select: none`
- `-webkit-touch-callout: none`
- `overscroll-behavior: none`
- 盤面領域の短い高さ向け `overflow: auto` を削除し、`overflow: hidden` に変更

これにより、セルから指を動かしたときに文字選択やページスクロールへ移らず、
盤面が残りの高さへ縮む。画面端の OS ジェスチャがアプリより優先される場合は、OS の動作を妨げない。

## 検証

- `pnpm --filter @sudoku/web typecheck`
- `flick.e2e.ts`: 右スワイプで 6 のパレット表示と入力を確認
- `layout.e2e.ts`: ページだけでなく盤面領域も縦スクロールしないことを確認

ブラウザ上の iPhone 相当ビューポートで検証している。iOS 実機の OS ジェスチャ優先順位や
Safari の表示バーの寸法は、実機での最終確認が必要である。
