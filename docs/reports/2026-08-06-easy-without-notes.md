# 検証: やさしいパックを候補メモなし向けに絞る

## 目的

「やさしい」は、候補メモを使わなくても解けるくらいにする。
表示名だけを変えず、解法手順と生成条件で確認できる契約にする。

## 実施日・条件

| 項目 | 値 |
|------|-----|
| 実施日 | 2026-08-06 |
| 対象 | `puzzles/packs/easy-000.txt` 全 1,000 問 |
| 評価 | `decodePack` で読み、`rateDifficulty` の `steps` を全件確認 |
| 候補メモなしの判定 | 全手順の `technique` が `naked-single` であること |
| 生成 | `easy-000`、1,000 問、8 ワーカー、最大試行数 500,000 |
| Node / pnpm | Node.js v24.18.0 / pnpm 11.18.0 |

`Naked Single` は、空きセル自身の候補が 1 個だけになる手筋である。
各セルの候補メモを盤面へ書き残さず、行・列・ブロックを確認して進められることを
「候補メモなし」の機械的な代理指標にした。

## 変更前の実測

変更前の easy パック(ハッシュ `22a5c7b8...`)を同じ評価で測った。

| 指標 | 値 |
|------|-----|
| 問数 | 1,000 |
| 難易度 | easy 1,000 問 |
| 手がかり数 | 21〜28、中央値 24 |
| 解法手数 | 53〜60、中央値 57 |
| スコア | 54〜92、中央値 70 |
| `naked-single` を含む問題 | 1,000 問 |
| `hidden-single` を含む問題 | 973 問(97.3%) |
| `naked-single` だけの問題 | 27 問(2.7%) |

従来の `easy` はレベル 1 なら採用していたため、クラス上は easy でも、ほとんどの問題が
Hidden Single を含んでいた。

## 変更後の実測

生成器に `EASY_MINIMUM_CLUES = 40` を置き、easy の試行だけ穴あけを 40 手がかりで止めた。
さらに、評価手順が `naked-single` だけの問題に採用条件を絞った。

| 指標 | 値 |
|------|-----|
| 問数 | 1,000 |
| 難易度 | easy 1,000 問、他クラス 0 問、評価不能 0 問 |
| 手がかり数 | 40〜40、中央値 40 |
| 解法手数 | 41〜41、中央値 41 |
| スコア | 41〜41、中央値 41 |
| `naked-single` だけの問題 | **1,000 問(100%)** |
| `hidden-single` を含む問題 | **0 問** |
| 生成試行 | 2,048 回 / 採用 1,000 問(48.8%) |
| 生成時間 | 0.3 秒(パック生成)、0.3 秒(全体) |

同じ条件で生成した easy パックのハッシュは `f7f85ed2...`。
manifest は `easy` 1,000 問を維持し、normal / hard / expert / extreme も各 1,000 問のままである。
後者 4 パックのハッシュは変更前後で一致した。

## 結論

easy は、解法手順を 100% `Naked Single` に限定したため、候補メモを使わずに進められるという
要望を手筋列で検証できる状態になった。手がかり数も 40 個に揃い、変更前の中央値 24 個・57 手
から 40 個・41 手へ短くなった。

難易度クラスの `rateDifficulty` 自体と、normal 以降の生成条件は変更していない。
人間が実際にメモなしで解く所要時間や体感はこの測定の範囲外であり、必要なら別途ユーザー試験で
突き合わせる。
