# 解法(ソルバ)

**ソルバは 2 種類ある。役割が違うので混ぜない。**

| ソルバ | 役割 | 使う場所 |
|--------|------|---------|
| **探索ソルバ** | 解を求める / **解の個数を数える** | 生成(一意解の判定)・遊技(答え合わせ) |
| **手筋ソルバ** | 人間の解法手順で解き、使った手筋を記録する | 難易度の評価・ヒントの提示 |

**探索ソルバは「解けるか」を、手筋ソルバは「どう解けるか」を答える。**
難易度は後者からしか出ない([難易度の評価](difficulty-rating.md))。

根拠は [数独の生成・難易度評価・ファイル形式の調査](../reports/2026-08-05-sudoku-generation-survey.md)。

## 盤面の表現

```
値      Uint8Array(81)    0 = 空き、1〜9 = 確定値
候補    Uint16Array(81)   ビットマスク。bit n が立っていれば数字 n+1 が入りうる
```

- **添字は 0〜80 の一次元。** 行 = `i / 9`、列 = `i % 9`、ブロック = `(row/3)*3 + col/3`
- **候補はビットマスクで持つ。** 交差・差集合がビット演算 1 回で済み、
  「候補が 1 個だけ」は `popcount === 1` で判定できる
- **行・列・ブロックの添字表は事前に作って使い回す。** 毎回計算しない

## 探索ソルバ

### 数え方

**「解を 2 個見つけたら打ち切る」。** これは複数の独立した実装で採られている定石である。

```
countSolutions(board, limit = 2) => 0 | 1 | 2
```

| 戻り値 | 意味 |
|--------|------|
| 0 | 解なし(矛盾している) |
| 1 | **一意解**(これだけが問題として成立する) |
| 2 | 複数解(2 個目を見つけた時点で打ち切ったので「2 以上」の意味) |

**「全部数える」必要は一度も無い。** 一意かどうかしか使わないため、
上限を付けないと最悪ケースで無駄に探索し続ける。

### 探索の進め方

1. **制約伝播を先に回す** —— 候補が 1 個のセルを埋める(naked single)、
   ある単位で 1 か所にしか入らない数字を埋める(hidden single)。
   矛盾(候補ゼロのセル)が出たら即座に失敗
2. **候補数が最小の空きセルを選ぶ**(most constrained variable)。
   分岐の幅が最小になり、探索木が小さくなる
3. その候補を 1 つずつ試して再帰する

**分岐する前に伝播を尽くす。** これを省くと探索木が桁で大きくなる。

### 性能の目安

公開されている高速実装(C++・SIMD)では、最難クラスでも**1 問あたり 100 μs 未満**。
**一意解の判定は生成のボトルネックにならない**([調査](../reports/2026-08-05-sudoku-generation-survey.md))。

⚠️ **これは C++ の値である。** TypeScript での実測は工程 2 で行う。
公開情報にも「JavaScript 版は非常に遅い」という記述がある。

## 手筋ソルバ

**人間が使う手筋だけで解き進め、使った手筋を順に記録する。**
探索(当て推量)を使わないのが決定的な違いである。

### 手筋の適用順

**簡単な手筋から順に試し、進んだら最初へ戻る。**

```
1. Naked Single       候補が 1 個のセル
2. Hidden Single      ある単位で 1 か所にしか入らない数字
3. Locked Candidates  Pointing / Claiming
4. Naked Pair/Triple/Quad
5. Hidden Pair/Triple/Quad
6. X-Wing / Swordfish / Jellyfish
7. XY-Wing / XYZ-Wing
8. チェーン系(X-Chain / Forcing Chain)
```

**この順序が難易度の定義そのものになる。**
順序を変えると同じ問題の難易度が変わるので、**順序は勝手に入れ替えない**。

### 出力

```
solve(board) => {
  solved: boolean,
  steps: Array<{ technique, cells, eliminated }>,
}
```

- `steps` は**適用した順**。難易度評価とヒントの両方がこれを使う
- **解けなかった場合も途中までの `steps` を返す。**
  「実装済みの手筋では解けない」ことが分かる

### 実装の範囲

**最初から全部の手筋を実装しない。** 工程 2 では 1〜5 まで(基本手筋)を作り、
6 以降は難易度クラスを広げる段階で足す。

**実装していない手筋があること自体は問題ではない。**
手筋ソルバで解けない問題を「その難易度クラスに入れない」だけでよい
([難易度の評価](difficulty-rating.md))。

## ヒントへの流用

遊技中のヒントは**手筋ソルバの最初の 1 手をそのまま出す**。

- 「どのセルに何が入るか」だけでなく、**なぜそう言えるか**(手筋名と根拠のセル)を出せる
- 答えを直接引くのではなく手筋を出すので、**遊技者が学べる**

⚠️ **ヒントは遊技者が入力した盤面に対して回す。**
元の問題に対して回すと、遊技者の入力(誤りを含む)と食い違う。

## テスト

[テストの方針](../verification/testing-policy.md) の「必ず守る性質」のうち、
ソルバが直接支えるのは次の 3 つ。

- 生成した問題は一意解である(探索ソルバ)
- 解いた結果が数独の規則を満たす
- 難易度の判定が安定している(手筋ソルバが決定的であること)

**手筋ソルバは決定的でなければならない。** 同じ盤面から同じ `steps` が出ること。
候補の走査順に乱数を混ぜない。
