# 問題ファイルの形式

**これは生成側(`generator`)と遊技側(`web`)をつなぐ契約である。**
片方だけを変えてはいけない。変えるときは**版を上げる**(下記「版の扱い」)。

**実装は `packages/core/src/puzzle-file.ts` に 1 つだけ置く。**
両側が同じ関数(`decodePuzzleLine` / `encodePack` / `tryParseManifest` など)を使う。
**web にも generator にも読み書きを書かない。**

根拠は [数独の生成・難易度評価・ファイル形式の調査](../reports/2026-08-05-sudoku-generation-survey.md)。

## 全体構成

```
puzzles/
├── manifest.json          収録内容の索引(これを最初に読む)
├── packs/                 同梱パック(Git 管理下)
│   ├── easy-000.txt
│   ├── normal-000.txt
│   └── ...
└── generated/             大量生成した追加分(Git 管理外)
```

**アプリはまず `manifest.json` を読み、必要なパックだけを `fetch` する。**
全パックを最初に読み込まない。

## パックファイル(`.txt`)

**1 行 1 問。** 81 文字 1 行が数独の事実上の標準形式であり、それに揃える。

```
<手がかり81文字>,<解81文字>,<難易度クラス>,<スコア>
```

例(実際は 81 文字):

```
53..7....6..195....98....6.8...6...34..8.3..17...2...6.6....28....419..5....8..79,534678912672195348198342567859761423426853791713924856961537284287419635345286179,easy,14
```

| 項目 | 内容 |
|------|------|
| 手がかり | 81 文字。**空きマスは `.`**、確定マスは `1`〜`9` |
| 解 | 81 文字。すべて `1`〜`9` |
| 難易度クラス | `easy` / `normal` / `hard` / `expert` / `extreme`([難易度の評価](../algorithms/difficulty-rating.md) の 5 段階) |
| スコア | 整数。同クラス内の並べ替えに使う |

**空きマスは `.` を書く。** 読み込み側は `0` も空きとして受理する
(既存の公開データセットは `0` を使うものが多く、取り込みたくなる場面があるため)。
**書き出しは常に `.` に統一する。**

### なぜ解も持つのか

**答え合わせのたびに解き直さないため。** 解は生成時に確定しているので、
81 バイト足すだけで遊技側のソルバ呼び出しを丸ごと省ける。

1 問あたり約 168 バイト。**1,000 問で約 164 KB、10,000 問で約 1.6 MB。**

### 行の順序

**難易度クラスとスコアの昇順で並べる。** 生成の到着順にしない。

**理由**: 並列生成すると到着順は毎回変わり、
**同じシードから同じファイルができるという保証(ADR 0003 の前提)が壊れる**。

## マニフェスト(`manifest.json`)

```jsonc
{
  "formatVersion": 1,
  "generatedWith": {
    "generator": "0.1.0",       // 生成器のバージョン
    "techniques": [1, 2, 3, 4]  // 実装済みの手筋レベル
  },
  "packs": [
    {
      "path": "packs/easy-000.txt",
      "difficulty": "easy",
      "count": 1000,
      "seed": "easy-000",       // これがあるので作り直せる
      "bytes": 168000
    }
  ],
  "totals": { "easy": 1000, "normal": 1000, "hard": 1000, "expert": 0, "extreme": 0 }
}
```

### 必ず入れるもの

| 項目 | 無いとどうなるか |
|------|----------------|
| `seed` | **管理外のパックを作り直せない。**[ADR 0003](../decisions/0003-external-puzzle-files.md) の前提が崩れる |
| `generatedWith.generator` | どの版の生成器が作ったか分からず、不具合の切り分けができない |
| `generatedWith.techniques` | **実装済みの手筋が増えると難易度の意味が変わる。**
  「当時のレベル 4 まで」で付いた難易度だと分かる必要がある |
| `count` | 読み込み前に件数が分かる。乱択で 1 問選ぶのに要る |

⚠️ **`generatedWith.techniques` を忘れやすい。**
手筋を実装するたびに難易度の基準は変わるので、
**古いパックの難易度を新しい基準と比べてはいけない**。

## 分割の方針

| 項目 | 方針 |
|------|------|
| 分割の単位 | **難易度クラスごと**。遊技者は 1 クラスしか使わない |
| 1 パックの件数 | **暫定 1,000 問**(約 164 KB) |
| 命名 | `<difficulty>-<連番 3 桁>.txt` |

**1,000 問で実測した**(2026-08-05・[検証](../reports/2026-08-05-puzzle-generation-benchmark.md))。

| パック | 生 | gzip | brotli |
|--------|-----|------|--------|
| 1,000 問 | 約 172 KB | 約 67 KB | 約 61 KB |

**1 問あたり約 172 バイト**で、上の見積もり(168 バイト)とほぼ一致した。
**圧縮すると 4 割弱まで落ちる**ので、独自形式で詰める必要は無い。
生成にかかる時間も 1 パック 0.7〜3.5 秒(8 並列)で、**件数の制約にはならない**。

- **圧縮は配信側(gzip / brotli)に任せる。** 独自形式で詰めない。
  81 文字のテキストは圧縮がよく効く
- **1 パックを大きくしすぎない。** 遊技者は 1 問しか遊ばないのに全体を落とすことになる

## 読み込み側の検証

**読み込み時に必ず検証する。** 壊れた問題を盤面に出さない
([システム構成](../architecture/system-architecture.md) のエラーハンドリング)。

⚠️ **読む側は例外を投げる関数を使わない。**
`core` には 81 文字を盤面へ読む関数が 2 つある。**用途が違う。**

| 関数 | 壊れた入力 | 使う場所 |
|------|-----------|---------|
| `tryParseBoard` | `null` を返す | **パックの 1 行を読むとき(こちらを使う)** |
| `parseBoard` | **例外を投げる** | テストの固定値・生成器の内部(壊れていない前提の場所) |

**`parseBoard` をパックの読み込みに使うと、1 行の破損でパック全体が落ちる。**
`decodePuzzleLine` も同じ理由で例外を投げず `null` を返す。

| 検証 | 落ちたら |
|------|---------|
| 4 列あるか | その行を捨てる |
| 手がかりと解が 81 文字か | その行を捨てる |
| 使える文字だけか(`.` `0` `1`〜`9`) | その行を捨てる |
| 解が手がかりと矛盾しないか | その行を捨てる |
| 難易度クラスが既知の 5 つか | その行を捨てる |

**行を捨てても、パック全体を捨てない。** 1 行の破損で 1,000 問が使えなくなるのは割に合わない。

⚠️ **解が本当に正しいか(数独の規則を満たすか)は読み込み時には検証しない。**
81 マスの規則検証を全問に掛けると起動が重くなる。
**正しさは収録前の検証で担保する**([テストの方針](../verification/testing-policy.md))。

## 進行の保存との関係

`localStorage` に持つのは**問題そのものではなく参照と差分**である。

```jsonc
{
  "packPath": "packs/easy-000.txt",
  "line": 42,                       // パック内の行番号
  "entries": [ /* 遊技者が入れた数字 */ ],
  "notes": [ /* メモ */ ],
  "elapsedMs": 123456,

  // 版の照合に使う(2026-08-05 追加)。下記の破棄の規約は
  // 保存側に版を持たないと判定できない
  "formatVersion": 1,
  "generator": "0.1.0",

  // ホーム画面が「続きから」を出すのに使う(2026-08-05 追加)。
  // パックの位置からも分かるが、そのためにファイルを取りに行かせない
  "difficulty": "easy"
}
```

**手がかりはパックから引き直せるので持たない。**

**保存しないもの**(2026-08-05 決定)。

| 対象 | 理由 |
|------|------|
| 完成した盤面 | 起動時に解き終わった問題が開く |
| 何も入っていない盤面 | 空の「続きから」が出る |
| 取り消しの履歴 | 保存が肥大する。**再開したら履歴は空**でよい |

**復元するとき、手がかりのマスに入っている値は捨てる。**
パックが差し替わって手がかりが増えていた場合に、
**書き換えられないマスへ入力が残るのを防ぐ**。

**経過時間は「増えた分を足す」形で持つ。**
開始時刻との差にすると、遊びかけを再開したときに前回のぶんが飛ぶ。

⚠️ **パックを差し替えると行番号がずれる。**
`formatVersion` か `generatedWith.generator` が変わったら、
**保存された進行は破棄して新しい盤面から始める**
(保存の失敗で遊べなくならないこと)。

## 版の扱い

**`formatVersion` を上げるのは、既存の読み込みコードで読めなくなる変更をしたとき。**

| 変更 | 版を上げるか |
|------|------------|
| 列を追加する | **上げる**(4 列前提の検証が落ちる) |
| 難易度クラスを増やす | **上げる**(未知のクラスを捨ててしまう) |
| マニフェストに項目を足す(省略可能) | 上げない |
| パックを増やす | 上げない |
