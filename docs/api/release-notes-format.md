# リリースノートの形式

**これは書く側(`docs/release-notes/`)と読む側(`packages/web` の閲覧機能)をつなぐ契約である。**
[問題ファイルの形式](puzzle-file-format.md) と同じ扱いで、**片方の都合で変えない。**

- **正本**は `docs/release-notes/<version>.md`。人が書く
- **配信物**は `packages/web/public/release-notes.json`。`tools/release-notes/build.mjs` が作る
- 書き方の手順は [`docs-release-notes` スキル](../../.claude/skills/docs-release-notes/SKILL.md)

⚠️ **配信物は Git 管理外である。** 手で編集しても次のビルドで消える。

## 正本(`.md`)

**1 版 1 ファイル。ファイル名は版そのもの**(`0.1.0.md`)。

````markdown
# 0.1.0 (2026-08-06)

## 追加

- 5 段階の難易度から選んで遊べます
- 候補の数字をメモできます

## 修正

- 画面の向きを変えると遊技が消えることがあったのを直しました
````

| 行 | 規則 |
|----|------|
| **1 行目** | `# <版> (<YYYY-MM-DD>)`。**版はファイル名と一致すること** |
| **節** | `## <名前>`。使えるのは **`追加` / `変更` / `修正` の 3 つだけ** |
| **項目** | `- ` で始まる 1 行。**複数行にまたがらせない** |
| 空行 | どこにあってもよい |

🔴 **上のどれにも当てはまらない行があると変換は失敗する。**
契約なので緩めない。書き損じを配信物へ通してしまうほうが害が大きい。

## 書き方の約束

| 約束 | なぜ |
|------|------|
| **読み手は遊ぶ人。開発者ではない** | 「`App.tsx` の早期 return を直した」ではなく「画面の向きを変えると遊技が消えることがあったのを直しました」 |
| **強調(`**`)を使わない** | 装飾は要らない。⚠️ **和文の強調は CommonMark で壊れやすい**([テストの方針](../verification/testing-policy.md)) |
| **1 項目 1 行、体言止めにしない** | 読み上げたときに文として通ること |
| **内部の用語を出さない** | パッケージ名・関数名・ADR 番号は書かない |

## 配信物(`.json`)

```json
{
  "formatVersion": 1,
  "releases": [
    {
      "version": "0.1.0",
      "date": "2026-08-06",
      "sections": [{ "title": "追加", "items": ["5 段階の難易度から選んで遊べます"] }]
    }
  ]
}
```

| 項目 | 内容 |
|------|------|
| `formatVersion` | この形式の版。**読む側は違う版を読まない** |
| `releases` | **新しい版が先頭**(semver の降順)。⚠️ **ファイルの読み込み順に依存させない** |
| `sections` | **正本に書いた順**。空の節は出さない |

## 既読の記録

**閲覧機能は「最後に読んだ版」だけを覚える。**

| 項目 | 値 |
|------|-----|
| 置き場所 | `localStorage` |
| 鍵 | `sudoku-web:release-notes-read` |
| 中身 | 版の文字列 1 つ(例: `"0.1.0"`) |

**未読の判定は「最新の版 ≠ 記録された版」。** 版ごとに既読を持たない。
**リリースノートは上から順に読むもの**なので、どこまで読んだかが分かれば足りる。

⚠️ **記録が無いとき(初回の起動)は「既読」として扱う。**
初めて遊ぶ人に過去の変更点を知らせても意味が無く、
**しるしが最初から付いていると「新しい知らせ」の意味が薄れる。**
このとき、閲覧機能を開いたかどうかに関わらず**最新の版を記録する。**

⚠️ **記録された版が配信物に無いとき**(版を取り下げたなど)も同じ扱いにする。
比較で落ちるより、しるしが出ないほうが害が小さい。

## 版の扱い

**[semver](https://semver.org/lang/ja/) に従う。**

| 上げるところ | いつ |
|-------------|------|
| メジャー(`1`.0.0) | 保存した遊びかけが読めなくなるなど、遊ぶ人に影響が出る変更 |
| マイナー(0.`1`.0) | 機能が増えたとき |
| パッチ(0.0.`1`) | 修正だけのとき |

**版は `package.json` の `version` と一致させる。** ずれたら `ops-release` スキルが止める。
