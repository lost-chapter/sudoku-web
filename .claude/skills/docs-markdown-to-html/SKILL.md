# Markdown を読みやすい HTML へ変換する

**この変換は純粋関数として扱う。** 同じ .md からは、いつ・どの端末で流しても
**バイト単位で同じ .html** ができること。これが崩れると差分が信用できなくなり、
「変換し直したのか、文書が変わったのか」が判別できなくなる。

## 契約(これを破ってはいけない)

| 性質 | 中身 |
|------|------|
| **決定性** | 同じ入力 → 常に同じ出力。**生成日時・乱数・実行環境の値を埋め込まない** |
| **入力を変えない** | `.md` を一切書き換えない。読むだけ |
| **副作用を出力先に限る** | 出力する `.html` 以外のファイルを作らない・消さない |
| **自己完結** | CSS と JS は**インライン**。CDN・外部フォント・外部スクリプトを参照しない |
| **オフラインで開ける** | ネットワーク無しでブラウザにドラッグして読める |
| **Git 管理外** | 生成物はコミットしない(`.gitignore` 済み) |

**「今日の日付」をヘッダへ入れたくなっても入れない。** 決定性が壊れる。
日付が要るなら .md 側に書く。

## 使い方

```bash
node tools/docs-html/render.mjs docs/guides/implementation-roadmap.md   # 1 ファイル
node tools/docs-html/render.mjs docs                                    # 再帰的に全部
node tools/docs-html/render.mjs docs --out /tmp/docs-html               # 出力先を変える
```

- 出力は**既定で入力と同じディレクトリ**に同名 `.html`。
  `docs/guides/handover.md` → `docs/guides/handover.html`
- 同じ場所に出すので、**`docs/assets/` への相対パスがそのまま効く**
- `--out` を使うときはディレクトリ構造を保って出力する(相対リンクを壊さないため)

## 出力 HTML の要件

**目的は「人間が読みやすいこと」。** 見た目を凝ることではない。

| 項目 | 要件 |
|------|------|
| 本文幅 | 1 行が長くなりすぎない幅で頭打ちにする(目安 40〜48em)。中央寄せ |
| 和文の可読性 | 行間を広めに取り、和文が読める font-family を指定する。**Web フォントは読み込まない** |
| 見出し | `h1`〜`h4` に階層が分かる余白と大きさ。見出しへ id を振る |
| 目次 | `h2` / `h3` から生成し、本文の前か横に置く。**見出しが 2 つ未満なら出さない** |
| 表 | 横に溢れたら**表だけが横スクロール**する。ページ全体は横スクロールさせない |
| コード | 等幅フォント。長い行は横スクロール。**シンタックスハイライトは任意**(入れるなら決定的に) |
| リンク | 相対リンクの `.md` を `.html` へ書き換える。外部リンク・アンカー(`#`)はそのまま |
| テーマ | `prefers-color-scheme` でライト/ダーク両対応 |
| 印刷 | 印刷しても本文が切れない(`@media print` で背景色を落とす) |
| タイトル | `<title>` は**文書の先頭の `h1`**。無ければファイル名 |

## 実装の要件

- **場所**: `tools/docs-html/render.mjs`(Node で直接動く単一ファイル)
- **パーサ**: `markdown-it`(GFM の表・チェックリストが要る)。
  自前でパーサを書かない
- **HTML エスケープ**: `markdown-it` の既定(`html: false`)を使い、
  .md 内の生 HTML は**エスケープして出す**。文書に書いたタグが実行されないこと
- **アンカー**: 見出しの id は**見出しテキストから決定的に**作る。
  重複したら連番を付ける(`-2`, `-3`)。乱数やハッシュの時刻依存を使わない
- **テスト**: `packages/` 側のテストと同じ枠組みで、次の 3 点を固定する
  1. 代表的な .md 1 本を変換した結果のスナップショット
  2. **2 回流して出力が完全一致する**(決定性)
  3. 入力の .md が変更されていない(副作用なし)

## 手順

1. **対象を確かめる** — どの .md を変換するのか。ディレクトリ指定なら何件になるか
2. **変換する** — 上記コマンド
3. **決定性を確認する** — 2 回流して差が無いこと

   ```bash
   node tools/docs-html/render.mjs docs && shasum docs/guides/*.html > /tmp/a.txt
   node tools/docs-html/render.mjs docs && shasum docs/guides/*.html > /tmp/b.txt
   diff /tmp/a.txt /tmp/b.txt && echo "決定的"
   ```

4. **Git を汚していないことを確認する** — `git status --short` に `.html` が出ないこと

   ```bash
   git status --short          # .html が出たら .gitignore が効いていない
   ```

5. **報告する** — 変換した件数と出力先。**中身の要約はしない**(変換しただけで内容は変えていない)

## よくある落とし穴

- **生成日時を埋め込む**: 決定性が壊れる。入れない
- **CDN の CSS を読む**: オフラインで開けなくなる。インラインにする
- **`.html` をコミットする**: `.gitignore` で除外済み。`git add -f` で強制追加しない
- **`.md` を「ついでに」直す**: この変換は読むだけ。文書の修正は別の作業として分ける
- **`--out` で構造を潰す**: フラットに出すと文書間の相対リンクが全部切れる
- **変換結果を根拠に文書の内容を語る**: HTML は .md の写しでしかない。
  内容の話をするときは .md を読む
