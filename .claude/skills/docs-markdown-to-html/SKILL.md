# Markdown を読みやすい HTML へ変換する

**この変換は純粋関数として扱う。** 同じ `docs/` からは、いつ・どの端末で流しても
**バイト単位で同じ出力**ができること。これが崩れると差分が信用できなくなり、
「変換し直したのか、文書が変わったのか」が判別できなくなる。

⚠️ **入力は 1 ファイルではなく `docs/` のツリー全体である。**
サイドメニューが全文書の一覧を持つため、**文書が 1 つ増えると全ページが変わる**。
これは壊れではなく、入力が変わったということ。

## 契約(これを破ってはいけない)

| 性質 | 中身 |
|------|------|
| **決定性** | 同じ入力 → 常に同じ出力。**生成日時・乱数・実行環境の値を埋め込まない** |
| **入力を変えない** | `.md` を一切書き換えない。読むだけ |
| **副作用を出力先に限る** | 出力する `.html` 以外のファイルを作らない・消さない |
| **自己完結** | CSS と JS は**インライン**。CDN・外部フォント・外部スクリプトを参照しない |
| **オフラインで開ける** | ネットワーク無しでブラウザにドラッグして読める |
| **Git 管理外** | 生成物はコミットしない(`.gitignore` 済み) |

**「今日の日付」をヘッダへ入れたくなっても入れない。** 決定性が壊れる。
日付が要るなら .md 側に書く。

## 使い方

```bash
pnpm docs:html                                              # docs/ → docs-html/
node tools/docs-html/render.mjs --src docs --out /tmp/x     # 入出力を変える
```

**出力は `docs-html/` に閉じる。`docs/` へは 1 バイトも書かない。**

```
docs/guides/handover.md   →   docs-html/guides/handover.html
docs/README.md            →   docs-html/index.html          ← 入口
docs/assets/*             →   docs-html/assets/*            ← 添付は複製する
```

- **`docs/` の構造をそのまま写す。** 文書間の相対リンクと添付への相対パスが
  そのまま効くのはこのため
- **入口は `docs-html/index.html`。** フォルダを開いてこれを叩けば読み始められる

実装は `tools/docs-html/`(2026-08-05 に工程 1 で導入)。

| ファイル | 中身 |
|---------|------|
| `render.mjs` | 変換の本体。`renderMarkdown()` が純粋関数 |
| `style.mjs` | 埋め込む CSS |
| `cjk-emphasis.mjs` | 和文で `**強調**` が効くようにする緩和(2026-08-06 に追加) |
| `highlight.mjs` | コードの色付け(ビルド時。2026-08-06 に追加) |
| `render.test.mjs` | 契約を守るテスト(`pnpm test` に含まれる) |

## 出力 HTML の要件

**目的は「人間が読みやすいこと」。** 見た目を凝ることではない。

**Markdown をそのまま流し込むのではなく、HTML だから効くものを入れる。**

### 版面

3 段(サイドメニュー | 本文 | ページ内目次)。狭い画面では 1 段へ畳む。

| 項目 | 要件 |
|------|------|
| **サイドメニュー** | **全文書の一覧をカテゴリ別に出し、どのページからでも移動できる**。現在のページに印(`aria-current="page"`)。**絞り込み入力**を付ける |
| **ページ内目次** | `h2` / `h3` から生成して右に固定。**いま読んでいる節を光らせる**(スクロール追従)。見出しが 2 つ未満なら出さない |
| **前後の導線** | サイドメニューと同じ並びで、前後のドキュメントへ進める |
| 本文幅 | 1 行が長くなりすぎない幅で頭打ちにする。中央寄せ |
| 和文の可読性 | 行間を広めに取り、和文が読める font-family を指定する。**Web フォントは読み込まない** |

### 読むための細工

| 項目 | 要件 |
|------|------|
| 見出し | `h1`〜`h4` に階層が分かる余白と大きさ。**id を振り、ホバーで見出しへのリンクを出す** |
| 表 | 横に溢れたら**表だけが横スクロール**する。ページ全体は横スクロールさせない。**画面より高い表は器の高さを止め、その中で見出し行を固定する。**⚠️ **`overflow-x` を付けた時点で縦もスクロールコンテナになる**ため、`th` の `position: sticky` はページのスクロールでは効かない。⚠️ **短い表まで器へ閉じ込めない**(スクロールが二重になる) |
| 表の状態 | **`✅` `❌` で始まるセルに淡く色を敷く。**⚠️ **濃くしない**。表が信号機になって読めなくなる |
| コード | 等幅フォント。長い行は横スクロール。**コピーボタン**を付ける |
| コードの色 | **色付けはビルド時に終え、出力にはクラス名だけを載せる**(ブラウザでハイライタを走らせない)。⚠️ **言語を推測しない**。指定の無いコードブロックは ASCII の図やコマンドの出力であり、色が付くと読みにくくなる |
| 引用と注意書き | `>` の段落と **`⚠️` で始まる段落**は注意書きとして扱い、地の文と見分けが付く見た目にする。⚠️ **引用の中では二重の箱にしない** |
| 和文の強調 | **`**完了。**次へ` のように約物で閉じた強調も強調として出す**。素の CommonMark は flanking 規則でこれを強調にせず、`**` を本文へ出してしまう(2026-08-06 の実測で 89 か所)。⚠️ **`md.inline.State` の prototype は書き換えない**(プロセス内の全 markdown-it に波及する)。書き方の側の対処は [ドキュメント管理規則](../../../docs/guides/documentation-guidelines.md) にある |
| 目次の見出し | **記法の記号を出さない。** `inline.content` は生の Markdown なので `**決定**` がそのまま目次に出る。解析済みの子トークンから地の文を集める |
| リンク | 相対リンクの `.md` → `.html`(`README.md` は `index.html`)。**`guides/` のようなディレクトリ参照はそのカテゴリの先頭ページへ繋ぐ**(HTML には索引が無く行き止まりになるため)。**外部リンクは別タブ + 印**。アンカー(`#`)はそのまま |
| テーマ | 既定は `prefers-color-scheme`。**手動で切り替えられ、選択は localStorage に残す** |
| 印刷 | サイドメニュー・目次・前後の導線を落とし、本文だけを出す |
| タイトル | `<title>` は**文書の先頭の `h1`**。無ければファイル名 |

## 実装の要件

- **場所**: `tools/docs-html/`(Node で直接動く。ビルド不要)

  | ファイル | 役割 |
  |---------|------|
  | `render.mjs` | CLI と組み立て。`renderPage()` が純粋関数の本体 |
  | `nav.mjs` | サイドメニューの並び。**カテゴリの順序はここに固定** |
  | `style.mjs` / `script.mjs` | 埋め込む CSS と JS |
  | `cjk-emphasis.mjs` / `highlight.mjs` | 和文の強調の緩和 / コードの色付け |

- **パーサ**: `markdown-it`(GFM の表が要る)。自前でパーサを書かない
- **色付け**: `highlight.js`(**ビルド時のみ**)。ブラウザへは 1 バイトも送らない
- **CSS と JS は文字列としてインラインで埋める。** 別ファイルにして読み込ませない
  (1 枚の .html を単体で人へ渡せる状態を保つため)
- **HTML エスケープ**: `markdown-it` の既定(`html: false`)を使い、
  .md 内の生 HTML は**エスケープして出す**。文書に書いたタグが実行されないこと
- **アンカー**: 見出しの id は**見出しテキストから決定的に**作る。
  重複したら連番を付ける(`-2`, `-3`)。乱数やハッシュの時刻依存を使わない
- **import しても走らない**: `render.mjs` は**直接実行されたときだけ** `main()` を呼ぶ。
  import しただけで変換が始まると「副作用は出力先だけ」の契約が壊れる
- **テスト**(`render.test.mjs`。`pnpm test` に含まれる)が固定していること
  1. 同じ入力から同じ出力になる(決定性)
  2. 日時らしき文字列を埋め込まない
  3. リンクの書き換え(`.md` → `.html` / `README.md` → `index.html` /
     ディレクトリ参照 → 先頭ページ / 外部リンクは触らず別タブ)
  4. サイドメニューに全文書が出て、現在のページに印が付く
  5. 生 HTML をエスケープする / 外部リソースを参照しない
  6. 入力の .md を書き換えない(副作用なし)
- **CI が決定性を見張る**(`.github/workflows/ci.yml` の「ドキュメント変換の決定性」)。
  2 回流して差が出たら落ちる

## 手順

1. **対象を確かめる** — `docs/` に何件あるか
2. **変換する** — `pnpm docs:html`
3. **決定性を確認する** — 2 回流して差が無いこと

   ```bash
   pnpm docs:html && find docs-html -type f | sort | xargs shasum > /tmp/a.txt
   pnpm docs:html && find docs-html -type f | sort | xargs shasum > /tmp/b.txt
   diff /tmp/a.txt /tmp/b.txt && echo "決定的"
   ```

4. **Git を汚していないことを確認する**

   ```bash
   git status --short          # docs-html が出たら .gitignore が効いていない
   ```

5. **報告する** — 変換した件数と入口(`docs-html/index.html`)。
   **中身の要約はしない**(変換しただけで内容は変えていない)

## よくある落とし穴

- **生成日時を埋め込む**: 決定性が壊れる。入れない
- **CDN の CSS や JS を読む**: オフラインで開けなくなる。インラインにする
- **`docs-html/` をコミットする**: `.gitignore` で除外済み。`git add -f` で強制追加しない
- **`docs/` へ .html を書く**: 出力は `docs-html/` に閉じる。正本の隣に生成物を置かない
- **`.md` を「ついでに」直す**: この変換は読むだけ。文書の修正は別の作業として分ける
- **出力の構造を潰す**: `docs/` と同じ構造を保つ。フラットに出すと相対リンクが全部切れる
- **「文書を足したら全ページの差分が出た」を壊れと誤解する**: サイドメニューが
  一覧を持つので当然そうなる。入力が変わっている
- **変換結果を根拠に文書の内容を語る**: HTML は .md の写しでしかない。
  内容の話をするときは .md を読む
