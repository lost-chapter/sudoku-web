# リリースノートを書く

**このスキルの目的は、リリースノートを「遊ぶ人が読んで分かるもの」にすることである。**

🔴 **コミットの一覧をそのまま並べない。** それは変更履歴であってリリースノートではない。
**遊ぶ人にとって何が変わったかだけを書く。**

形式の契約は
[リリースノートの形式](../../../docs/api/release-notes-format.md) にある。**そちらが正である。**

## 完了条件

```bash
node tools/release-notes/build.mjs                 # 形式が通る
node --test tools/release-notes/build.test.mjs     # 正本を見張るテストが通る
pnpm docs:lint                                     # 和文の強調が壊れていない
```

**そのうえで、書いたものを声に出して読んで、遊ぶ人に通じるかを確かめる。**
🔴 **検査は形式しか見ない。中身が通じるかは人が読んで決めるしかない。**

## 1. 何が入ったかを集める

```bash
git tag --list 'v*' | tail -3                      # 前の版
git log --oneline v0.1.0..develop | cat            # 前の版から入ったもの
```

**初めての版なら**、[実装の進め方と現在地](../../../docs/guides/implementation-roadmap.md)
の工程表から「動くようになったこと」を拾う。

⚠️ **コミットの数と項目の数は合わない。** 1 つの機能が 10 コミットに分かれていることも、
10 コミットが遊ぶ人にとって 1 行にもならないこともある。

## 2. 落とすものを落とす

**遊ぶ人に見えないものは書かない。**

| 落とすもの | 例 |
|-----------|-----|
| 内部の作り替え | パッケージの分割、型の整理、命名の変更 |
| テスト・CI・開発環境 | テストを足した、CI のジョブを増やした |
| ドキュメント | ADR を書いた、図を mermaid にした |
| 出す前に直した不具合 | **前の版に無かった不具合は、遊ぶ人にとって存在しない** |

⚠️ **最後の 1 つを間違えやすい。** 「レイアウト切り替えで遊技が消える」を直したとしても、
**その不具合が前の版に無かったなら書かない。** 遊ぶ人は遭遇していない。

## 3. 開発者の言葉を遊ぶ人の言葉へ直す

| ❌ 開発者の言葉 | ✅ 遊ぶ人の言葉 |
|---------------|---------------|
| `App.tsx` の早期 return を外して要素の同一性を保った | 画面の向きを変えると遊技が消えることがあったのを直しました |
| `isSolvedByPlayer` を追加し完成判定を分離 | あきらめたときに「完成しました」と出ないようにしました |
| `PHONE_QUERY` による専用レイアウトを実装 | スマートフォンでは画面いっぱいに盤面を出す見た目に切り替わります |
| 手筋ソルバにレベル 5〜7 を追加 | 難問と最難関で遊べるようになりました |

**言い換えの手がかり。**

- **その変更で、遊ぶ人の画面や手元の操作が、どう変わったか**を書く
- **理由や仕組みは書かない。** 「〜のため」「〜によって」が出たら削る
- **パッケージ名・関数名・ファイル名・ADR 番号を出さない**

## 4. 3 つに振り分ける

| 節 | 入れるもの |
|----|-----------|
| `追加` | **できることが増えた**とき |
| `変更` | **できることは同じだが、やり方や見え方が変わった**とき |
| `修正` | **前の版で困っていたことが解消した**とき |

⚠️ **迷ったら「遊ぶ人が前の版で何をしていたか」で決める。**
前の版でできなかった → `追加`。できていたが違う形だった → `変更`。
できるはずが困っていた → `修正`。

**空の節は書かない。** 3 つ全部を埋めようとしない。

## 5. 書く

`docs/release-notes/<版>.md` を新規に作る。**既存の版を書き換えない。**

````markdown
# 0.2.0 (2026-08-10)

## 追加

- 難問と最難関でも遊べるようになりました

## 変更

- ボタンの文字を絵に変えて、狭い画面でも押しやすくしました

## 修正

- 画面の向きを変えると遊技が消えることがあったのを直しました
````

**書き方の約束。**

| 約束 | なぜ |
|------|------|
| **1 項目 1 行** | 変換が複数行を受け付けない |
| **「〜ました」「〜ます」で終える** | 体言止めが混ざると読み上げたときに文にならない |
| ⚠️ **強調(`**`)を使わない** | 装飾は要らない。**和文の強調は CommonMark で壊れやすい** |
| **日付は出す日** | ⚠️ 書いた日ではない。ずれたら出す日へ直す |
| **版はファイル名と見出しの両方** | 片方だけ直すと変換が落ちる |

## 6. 確かめる

```bash
node tools/release-notes/build.mjs
cat packages/web/public/release-notes.json         # 新しい版が先頭に来ているか
pnpm docs:lint
```

**アプリで実際に読む。**

```bash
pnpm dev
```

⚠️ **画面で読んで初めて分かることがある。** 1 行が長すぎて折り返す、
項目が多すぎて終わりまで届かない、など。

## よくある落とし穴

| 落とし穴 | どうなるか |
|---------|-----------|
| 🔴 **コミットの要約を並べる** | 遊ぶ人が読んでも何が変わったか分からない |
| 🔴 **出す前に直した不具合を「修正」に書く** | 遭遇していない不具合を知らされて不安になる |
| **内部の用語が残る** | 「`localStorage` に保存」「ADR 0005 に従い」など。3 の表で潰す |
| **理由を書いてしまう** | 「押しやすくするために絵に変えました」→ 「絵に変えて押しやすくしました」 |
| **既存の版を書き換える** | 既に読んだ人と食い違う。追記が要るなら次の版へ書く |
| **日付を書いた日にする** | 出す日と違うと、遊ぶ人には未来か過去の日付に見える |
| **3 つの節を全部埋めようとする** | 中身の無い項目が増える。空の節は書かない |
